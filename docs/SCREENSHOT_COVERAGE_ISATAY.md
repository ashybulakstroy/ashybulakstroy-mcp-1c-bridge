# Screenshot Coverage: Isatay

Этот документ фиксирует, что именно уже совпадает между экраном 1С `Isatay` и read-only MCP tools.

Статусы:
- `covered`: поле или экран уже читается через tool
- `partial`: поле частично читается или дается в упрощенном виде
- `not available`: в текущей OData-публикации честно не восстанавливается

## Бухгалтерский блок продаж

Текущее состояние:
- смысл счетов по строкам реализации восстанавливается через `Catalog_КорреспонденцииСчетов`
- tool показывает:
  - `Товары`
  - `Доход от реализации`
  - `Себестоимость реализации`

Ограничение:
- точные коды `1330 / 6010 / 7010` в текущей OData-публикации `Isatay` не найдены
- явного `ChartOfAccounts_*` published source нет

Статус:
- `Смысл счетов`: `covered`
- `Точные цифровые коды счетов`: `not available`

Ограничение:
- в `Isatay` по части счетов `Склад_Key` приходит как zero-guid, поэтому tool честно отдает `None`, а не фиктивное значение
- в `Isatay` поле `СтруктурнаяЕдиница` у части счетов приходит как typed reference на банковский счет, поэтому tool честно показывает resolved bank account display, а не выдумывает другое значение

## Что еще осталось

- Добить consistency по `Счет на оплату` и `Документ расчетов` на разных типах реализаций
- При необходимости добавить отдельный `sales accounting view` tool, если бизнесу нужен отчет именно по аналитикам проводок
- Если 1С-сторона когда-либо опубликует plan of accounts, заменить inferred labels на точные коды счетов
